# 首次导入、通知兼容与侧边栏问候语修复设计

## 背景

本轮真机检查发现四类问题：

1. 导入页长期展示 HTTP 安全提示，但桂林、南宁教务均由校方固定使用 HTTP。
2. 桂林校区首次导入可能显示考试数为 0，而考试页手动刷新能够取得数据；南宁校区首次导入正常。
3. 覆盖安装后通知页可能显示“暂无通知”，清除应用数据后恢复。
4. 较长问候语在侧边栏头部被强制单行省略。

## 设计决策

### 教务 HTTP 边界

移除导入页可见的安全提示，不改变用户操作流程。底层继续只对桂林、南宁教务官方域名开放明文 HTTP，并继续校验会话请求目标，避免把 Cookie 发送给非教务域名。

### 考试首次导入

首次导入不再直接从通用探测结果中挑选单个考试响应，而是复用考试页的 `AcademicExamService`。该服务负责尝试已知考试接口、拒绝空解析结果并记录成功接口。只有获得非空考试列表时才替换本地考试缓存；失败时保留旧缓存并把“考试”加入部分失败模块。

这样桂林和南宁使用同一条稳定链路，同时避免把桂林某个接口返回的可识别空结构误判为成功。

### 通知覆盖升级兼容

通知继续采用缓存优先，但网络刷新从版本更新检查中拆出，避免两者串行阻塞。界面状态明确分为：

- `Loading`：无缓存且首次刷新未结束；
- `Content`：存在可展示通知；
- `Empty`：联网成功且服务端确实返回空列表；
- `Error`：无可用缓存且刷新失败。

旧缓存若无法解析，不直接把它解释成“暂无通知”，而是等待网络刷新。刷新失败时保留现有缓存，并提供“重新加载”入口。该方案兼容覆盖安装遗留状态，也避免用户必须清除课程、设置等全部应用数据。

### 侧边栏问候语

抽屉宽度维持屏幕的 75%。头部改为两层：

1. 第一层只显示 Logo 和“桂系一站式”；
2. 第二层使用完整可用宽度显示问候语，最多两行。

问候语预留固定两行高度，打字过程中菜单位置不跳动；超过两行时才省略。无障碍语义始终保留完整文本。

## 验证要求

- 单元测试覆盖考试空结果拒绝、首次导入复用考试服务、通知状态推导及重试行为。
- Compose 契约测试覆盖安全提示移除和问候语双行约束。
- 执行完整 `testDebugUnitTest` 与 `assembleDebug`。
- ADB 恢复后验证桂林首次导入、南宁首次导入、覆盖安装通知页、通知重试以及长问候语布局。
