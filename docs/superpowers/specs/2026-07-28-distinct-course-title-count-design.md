# 安卓与微信端课程门数统一设计

## 背景

课表为了准确表达不同教室、教师、星期、节次和周次，会把同名课程拆成多个本地课程实体。当前安卓端使用 `courses.size`、微信端使用 `courses.length` 作为“课程门数”，因此桂林 2026 春的 12 个唯一课程名称被显示为 38 门课程。38 是内部课表实体数，不是用户语义中的课程门数。

## 目标

- 安卓端和微信端统一按课程名称统计课程门数。
- 桂林和南宁使用完全相同的统计规则。
- 学期概览、首次导入结果、重新下载或刷新课表提示中的课程数量保持一致。
- 保留底层按教室、教师和时段拆分的课程实体，课表卡片显示不受影响。

## 非目标

- 不修改课表解析器的课程分组规则。
- 不合并 Room 或微信缓存中的课程实体。
- 不改变成绩、培养方案等独立业务模块的课程计数。
- 不改变“是否存在课表”的判断；非空判断仍以是否存在课程实体为准。

## 统一统计规则

两端各提供一个小型纯函数：

```text
课程门数 = 去重集合大小(
  每个课程实体的 title
  → 去除首尾空白
  → 将连续空白压缩为一个空格
  → 丢弃空名称
)
```

判定标准只有规范化后的课程名称。教师、教室、校区、星期、节次、周次、课程 ID 均不参与去重。

保留大小写和其他字符，不做模糊匹配，避免把实际名称不同的课程错误合并。

## 安卓端

在课表领域层附近增加可复用的课程名称计数函数，供以下位置调用：

- `SemesterOverviewViewModel`：学期概览课程数量。
- `DirectLoginViewModel`：首次导入结果中的课程数量。
- `ScheduleViewModel`：重新下载或刷新学期课表的前后课程数量提示。

解析器、Repository 和数据库仍保存全部拆分实体。

## 微信端

在通用课表工具中增加同语义的课程名称计数函数，供以下位置调用：

- `utils/semesterOverview.js`：历史学期概览课程数量。
- `pages/import/import.js`：首次导入、最新学期导入和历史学期下载结果中的课程数量。

缓存状态与空课表判断仍使用实体数组是否为空，不把统计函数用于控制数据流程。

## 测试

两端均先写失败测试，再实现：

1. 同名课程在不同教师、教室、时段出现时只计为一门。
2. 课程名称首尾空白或连续空白不同仍视为同一门。
3. 不同课程名称分别计数。
4. 空名称不计入课程门数。
5. 学期概览和导入结果使用统一函数，而不是实体数组长度。
6. 运行安卓完整单元测试与 Debug 构建。
7. 运行微信端完整 `node --test`。

## 验收标准

- 桂林 2026 春的内部 38 个课程实体，在课程门数位置显示为 12。
- 安卓与微信端结果一致。
- 桂林与南宁遵循相同规则。
- 课表卡片数量、教师、教室和时段显示不发生变化。
